太仓港断电指导 APP 改进优化方案

基于 V4.1 版本代码审查 · 2026-08-20 · Taicanggang Dev Team

一、安全（优先级：高）

1. 飞书 App Secret 前端内置泄露风险 建议尽快处理

当前 DEFAULT_FEISHU_CONFIG 将 App ID / App Secret 硬编码在 demo.html 中，任何人解包 APK 或查看网页源码即可获得，可被用于读写云盘文件夹。

方案：部署一个轻量代理服务（如云函数/Render 免费实例），前端只调代理地址，Secret 保存在服务端环境变量；或改用飞书「自建应用 + user_access_token」模式，权限跟随用户。过渡期最低限度：在飞书后台限制该应用可访问的目录范围、开启 IP 白名单。

2. 账号体系明文存储 中期

用户账号（手机号+密码）以明文 JSON 存于 localStorage，且审核状态可被用户在控制台自行修改。

方案：密码改哈希（Web Crypto SHA-256+盐）；组长/组员权限判断所需的关键状态随同步数据一起存云端并在登录时校验，避免纯本地可篡改。

3. CSP 加固 低成本

已对所有动态内容做 esc() 转义，建议再加 <meta http-equiv="Content-Security-Policy"> 白名单（self + jsdelivr + tailwind + feishu/github API），即使未来出现转义遗漏也能兜底。

二、工程与可维护性（优先级：中高）

4. 单文件 197KB 的 demo.html 拆分 中期

所有 HTML/CSS/JS 集中在一个文件，多人协作与回归成本高。

方案：按模块拆分（数据层 / 飞书服务 / 更新服务 / 页面组件），引入 Vite 构建，产出仍是单文件或少量文件； Cordova www 直接使用构建产物。

5. 版本发布自动化 推荐

当前 version.json（版本号、更新日志、APK 大小、下载地址）手工维护，易出现不一致（本次就出现过 v3.1/v4.0 混显示）。

方案：构建脚本自动生成 version.json（读 config.xml 版本号 + 记录 APK 实际大小），Release 上传成功后回填下载地址；GitHub Actions 自动构建+发版，摆脱对本地 Node/Cordova 环境的依赖（本次本地 node_modules 损坏导致构建中断多次）。

6. 数据层统一 中期

内置 VEHICLES、localStorage 修改副本、云端 vehicle_sync_data.json 三个数据源，同步合并策略为整体覆盖，多端并发编辑会互相丢失修改。

方案：引入 Repository 层统一读写；记录每条车辆的 updatedAt，同步时做字段级合并（最后写入优先 + 冲突清单提示用户确认）。

三、功能与体验（优先级：中）

7. 更新下载链路增强

GitHub Release 直链在国内移动网络可能不通。version.json 已含 feishuFolder 字段，建议：检测到 GitHub 下载失败时提示飞书云盘备用入口；或提供 jsDelivr 代理的 version.json 作为第二源（已实现）+ 飞书盘直链作为 APK 备用源。

8. 离线与性能

  • 112 张图片 + 47 个视频全部随包分发（APK 39MB）；改为首次查看时按需加载 + 本地缓存，可显著减小安装包
  • 车辆列表渲染一次性插入全部 DOM，数据量增大后可做分页/虚拟列表
  • 视频选择 ≤100MB 且 base64 暂存，编辑大视频时内存峰值高；建议直接引用文件路径（Cordova FILE URL）

9. 崩溃与问题回传

目前无错误收集。建议：window.onerror / unhandledrejection 记录到 localStorage 环形队列，同步时一并向飞书上传 error_log.json，便于定位现场问题。

四、实施建议排期

阶段事项预估工作量
立即（1天内）飞书应用目录范围收紧 + IP 白名单；构建脚本自动生成 version.json0.5 天
短期（1周内）密码哈希；CSP；错误日志回传；更新备用下载源2–3 天
中期（2–4周）Secret 代理化；工程拆分 + Vite；数据层 Repository 与字段级合并；CI/CD1–2 周
