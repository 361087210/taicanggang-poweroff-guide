- **常见故障表**：`Multiple artifacts named "github-pages"`（不要重跑，用全新 dispatch）、规则集拒推、改名迁移未完成、照片 404、白屏（复制诊断信息）
- **季度恢复演练**：从备份恢复 → 对比 diff → 记录耗时
- **值班升级路径**

## 二、严格规则集模板

`.github/rulesets/branch-strict.json`（`pull_request` + `required_status_checks`：`Web资产与安全校验` / `scan`）与 `tag-protect.json`。

> 当前生效的是「禁 force push / 禁删除 / 线性历史」三条。**升级到强制 PR 的前置条件**已写进 RUNBOOK：机器人 PR 必须能拿到必需检查（`GITHUB_TOKEN` 创建的 PR 目前拿不到，需要 `SYNC_TOKEN` 直推或显式派发检查）。

## 四、测试健壮性

两处写死数据量的断言改为动态互证：

| 位置 | 旧断言 | 新断言 |
|---|---|---|
| `test_v10263_shared_refs` | 真缺失 `=== 64` | 与索引 `missing` 明细数一致 |
| `test_v10266_media_independence` | 车型 `=== 100` | 索引车型数 == 镜像车型数 |

> 动机：数据每 15 分钟可能变化，写死数量会让"数据变多"看起来像"代码坏了"——这也是依赖升级 PR 与自动同步 PR 反复变红的同类根因（脆弱断言）。
