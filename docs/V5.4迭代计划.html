V5.4 迭代计划

基于V5.3交付审查与同类产品(现场作业SOP类APP)市场方案对比 | 2026-08-20

一、计划背景

V5.3已完成真机CORS根因修复、数据分仓、审批闭环、返回键统一路由等9项修复与90项测试。但对照行业成熟方案（钉钉审批、企业微信现场作业、蓝凌/泛微移动OA、YouTube类媒体方案），仍有以下结构性短板需要在V5.4系统性解决。

核心矛盾：应用已从"单机工具"演进为"多人协作平台"，但架构仍是单文件SPA + 60秒轮询 + 明文密码，协作规模超过10人/日活后必然遇到性能与安全瓶颈。

三、P0 详细方案

3.1 密码安全加固

问题：当前 approved_users.json 以明文存储密码并上传飞书云盘，任何拿到云盘读权限的人可見全部密码。审批闭环V5.3反而放大了暴露面。

方案：注册时前端 SHA-256(密码+手机号盐) 后仅存哈希；登录比对哈希；历史明文账号启动时一次性迁移。飞书侧只同步哈希值。

风险控制：迁移兼容期保留明文比对回退一个版本，V5.5移除。

3.2 代码模块化重构

问题：demo.html已达241KB/5000+行，任何编辑都有全局污染风险，测试只能黑盒。这也是历次"改A坏B"返工的根源。

方案：按 Feature-based 目录拆分（符合项目编程规范）：

src/
├── features/
│   ├── auth/        # 登录/注册/审批
│   ├── vehicles/    # 车辆列表/详情/编辑
│   ├── media/       # 图片视频查看/上传/迁移
│   ├── export/      # Word/PDF/Excel导出
│   ├── sync/        # httpFetch/飞书服务/数据分仓
│   └── settings/    # 我的/版本检查
├── core/            # 路由/返回键/存储/全局错误
└── components/      # 通用UI组件

策略：Cordova www 目录直接放构建产物，保留"单文件可用"的浏览器预览能力（Vite单文件插件）。

3.3 CI/CD 自动化

问题：每次发版依赖手工bat脚本+手动同步GitHub/飞书，本次构建还因网络代理问题排障1小时+。

方案：GitHub Actions：push tag(v*)→自动跑90项测试→Gradle签名构建→创建Release→webhook通知同步飞书。keystore用GitHub Secrets加密存储。

四、P1/P2 摘要

  • 数据冲突解决：当前后写覆盖(shadow write)，双组长同时编辑必丢数据。引入每记录 version+updatedAt，下载时三方合并，冲突弹窗人工裁决。
  • 视频优化：上传前ffmpeg压缩(1080p→720p/1.5Mbps)，>5MB分片上传+断点续传；详情页生成首帧缩略图，列表不再加载整段视频。
  • 离线优先：车辆数据全量入IndexedDB，云端变更增量拉取；弱网时全部只读+队列写，恢复网络自动同步。港口现场网络差是常态。
  • 实时审批：飞书开放平台事件订阅(长连接模式)，组员提交瞬间推送到组长设备，替代60秒轮询延迟。
  • AR标注：操作步骤照片叠加箭头/圆圈高亮断电点位，参考高端车企技师端，降低现场误操作率（长期差异化亮点）。
  • iOS移植：Cordova→Capacitor（插件兼容层现成），产出iOS安装包，覆盖苹果用户组员。

五、建议里程碑

第1-2周P0三项：密码哈希迁移 + 模块化重构 + CI/CD流水线
第3-4周P1三项：冲突解决 + 视频分片 + 离线优先
第5周灰度发布：组长设备先行，全组验证一周
第6周+P2按需启动：实时推送 / AR标注 / iOS

注：工作量按单人全职估算；建议V5.4冻结新功能需求，专注架构还债。
