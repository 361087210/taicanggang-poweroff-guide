# V10.27.9 媒体资源治理版

> 一句话：按《媒体资源与 COS 播放源对照审查》把三块 P0/P1 差距补齐 —— 删除可恢复（回收站）、
> COS 国内源接入、资源库改为媒体单一真源。

## 为什么做这一版

对照审查发现三个真实问题：

1. **删除不可恢复**：资源库删一张照片会直接删云端文件并改写车型引用，误删只能靠备份。
2. **播放/看图依赖境外链路**：同一 4MB 片段走 GitHub Release 实测 1.9s / 29.6s / 108s（甚至超时零字节），
   现场网络下开图很慢。
3. **媒体数据不是单一真源**：资源库上传/删除会整份覆盖 `vehicle_sync_data.json` —— 两台设备各改不同车型
   也会互相覆盖；某设备的旧快照再同步一次，已删的图会“自己回来”（而云端文件已无 → 永久缺失）。

## 改了什么

### 1. 回收站（软删除，P0）

- 删除 = 回收站记录（`localStorage.tcg_media_trash`）+ 媒体登记表墓碑；**云端文件保留**
- 记录保存路径、归属车型、媒体类型、原因与时间
- 「恢复」只摘墓碑与记录；「彻底删除」才真正调用 `driveDeleteFile`，并保留清理墓碑防止旧快照复活

### 2. COS 国内源（P1）

- 新增 `TCG_CONFIG.MEDIA_COS_BASE`（腾讯云对象存储公有读桶，ap-shanghai）
- 照片：本地 → 候选路径（车型目录 → `_共享` → 顶层）→ COS → 飞书 → 诚实空态
- 视频：播放源注册表为「CDN → COS → GitHub → 飞书」候选链，未命中安静回退，不弹错
- 未配置 `MEDIA_COS_BASE` 时行为与上一版一致

### 3. 媒体单一真源（P0/P1）

- 资源库只写媒体登记表：本地 `tcg_media_registry` + 云端 `media_registry.json`
- 上传：判重（同名同内容首尾采样哈希）→ 上传 → 登记；登记写盘失败则**回滚**刚上传的云端文件
- 删除/恢复：写墓碑 / 摘墓碑，不再改写车型 payload
- 渲染：车型列表、详情、照片查看器、视频播放器统一走 `mediaViewPaths` / `mediaViewMeta`，
  合并「车型基线 + 登记表」
- 同步下载：增量拉取登记表并做并集（下载→并集→上传），按 `at` 取最新（LWW），同时间删除优先

## 影响面

- 误删可恢复，组员不再因为删错图去翻备份
- 现场开图/看视频多一条国内直链，弱网成功率提升
- 多设备同时维护媒体不再互相覆盖；旧快照回传不会让已删文件复活
- 台账统计口径与回收站一致（墓碑行不再出现在正常/共享/缺失里）

## 已知边界

- 导出模块（Word/PDF/Excel）仍直接读车型基线，未纳入本次合并视图范围（车型侧数据未变，导出结果与上一版一致）
- COS 只同步了基线素材，未命中会自动回退，不影响可用性
