# 太仓港商品车断电操作标准化指导平台 v10.25.4

> **发布日期**：2026-11-10
> **版本代号**：媒体链路修复版

## 一句话

把「该传的没传」「显示别人的图」「云端顶层散落」三个症状从链路上根治。

## 修的三件事

### 1. 上传幂等跨车型污染

判重键由「裸文件名」改为「**车型目录/文件名**」。

旧实现把所有子目录的文件名倒进同一个 Set：A 车型目录里的 `image1.jpeg` 会让 B 车型的同名文件被判"已上传"而跳过 —— 该传的没传；解析时又可能命中 A 的文件 —— 显示别人的图。一个集合同时制造两个症状。

### 2. 子目录创建失败不再降级顶层

旧代码失败时静默返回顶层 token（只有一行 console 告警），照片全堆进 `vehicle_images/` 根目录 —— 这是云端 199 个文件散在根上的直接来源。

现在：重试一次（含同名目录复列，处理"另一台设备刚建好"）→ 仍失败即抛错，外层记为 failed 并保留本地 base64 下轮重试。**宁可这次没传，也不留无法归属的散文件。**

### 3. 客户端候选路径回退

新增 `mediaCandidateSrcs()`，加载失败依次尝试：

```
原路径 → _共享/同名 → 顶层/同名
```

全部失败才回退飞书云端，最后才显示「缺失」。**只试"同名不同目录"，绝不跨名猜测** —— 断电教学照片看错车型是现场安全问题。
