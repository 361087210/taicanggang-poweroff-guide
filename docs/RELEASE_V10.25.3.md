# 太仓港商品车断电操作标准化指导平台 v10.25.3

> **发布日期**：2026-11-09
> **版本代号**：视频播放提速版

---

## 一句话

把 `media-videos` Release 里的 65 个视频资产从 **4.6 GB 压到 490 MB**，
全部换成 720p + faststart 转码件——手机 4G 从"分钟级等待"变成"秒级起播"。

---

## 为什么这么改

App 的视频回退链里，**源②（GitHub Release 直链）是首选的快速源**：免鉴权、支持 Range、可拖动。
但此前该 Release 里的资产**全是原始体积**：

| 修改前 | 修改后 |
|---|---|
| 单文件最大 **332.6 MB** | 单文件最大 **17.3 MB** |
| 65 个资产合计 **4644 MB** | 合计 **490 MB** |
| 4G 下约 6–15 分钟才起播 | **秒级起播** |
| 需全量下载才能播 | `+faststart`，边下边播 |

（原始片码率 8–20 Mbps，现场 4G 实际可用 1–3 Mbps，这就是"视频加载很慢"的算术原因。）

---

## 做了什么

### 1. 21 组飞书分片 → 合并 → 转码 → 上传

`vehicle_videos` 里 156 个 `.part` 分片分属 21 组，**没有一组存在同名整片**——
即这 21 个视频当时只有碎片形态。处理链路：

```
156 分片下载 → 按序拼接 → 校验 ftyp → 转码 720p → 上传整片 → 归档分片
```

| 指标 | 数值 |
|---|---|
| 合并原始体积 | 约 1.7 GB |
| 上传体积 | **198 MB** |
| 归档分片 | 156 个（→ `_回收站/20260911/`，可恢复） |

**为什么必须转码**：飞书单次上传接口硬上限 **20 MB**，原始片均值 80 MB 传不上去。

### 2. Release 资产全量替换

| 阶段 | 替换数 | 体积变化 |
|---|---|---|
| 第一轮（21 个合并视频） | 21 | 2550 MB → 198 MB |
| 第二轮（9 个超大存量资产） | 9 | 1896 MB → 约 90 MB |
| 合计 | 30 | **4644 MB → 490 MB** |

第二轮有 9 个资产在飞书云端已无原件，直接从 Release 拉回旧资产当源转码替换。

### 3. 映射修正

- 补齐「柳工2.5T叉车」直链
- 修正「长安皮卡_HUNTER」因资产重名产生的 `_2` 后缀
- 映射条目 52 → **53**

## 转码参数

```
只降不升：scale='if(gte(ih,720),-2,iw)':'if(gte(ih,720),720,ih)'
逐级压缩：crf 26 → 30 → 34（保证 ≤19.5MB）
编码：libx264 high/4.0 + AAC 96k 单声道 + faststart
```

## 升级说明

- App 内更新后**重启一次**（`sw.js` 缓存名已升级）
- 视频无需重新上传，客户端按映射自动切到新资产
- 原始画质保留在飞书 `_回收站/20260911/` 的分片里，**确认新版本可播之前不要清理回收站**
