# V10.27.3 播放源可配置版

> 一句话：把"视频从哪儿播"从写死的单一 GitHub Release，改成**可配置的候选链**
> （对象存储 CDN 主 → Release 备），并给每个源加 30 分钟健康记忆。
> 换播放源从此是**改一行配置**，不是改播放链路代码。

## 为什么现在做

`docs/VIDEO_SOURCE_EVAL.md` 的实测结论（同一网络、同一时段、每次 4MB）：

| 源 | 首字节中位 | 吞吐中位 | 最差 | 备注 |
|---|---|---|---|---|
| GitHub Release | 0.61s | 418 KB/s（另一轮 138） | **38 KB/s** | 三次同一片段 1.9s / 29.6s / 108.0s，还出现过 45s 超时零字节 |
| 飞书 drive（带 token） | 0.63s | 4037 KB/s | 4015 KB/s | 稳定，但必须带 `tenant_access_token`，前端拿不到 |
| 对象存储（待测） | — | — | — | 预期 ≈4.2 分（加权），需先填 12 问清单 |

结论是**真源与播放源分离**：飞书继续当真源，播放走对象存储 CDN 为主、Release 为备。
但"换源"这件事此前是**写死在代码里**的——`mediaDirectUrl()` 只返回一个 GitHub URL，
主源一旦不可用，播放链路会直接掉进需要密钥的飞书源，网页端那等同于空态。
本版把这段能力补上，让后续接入对象存储只改 `TCG_CONFIG.MEDIA_CDN_BASE` 一行。

## 改了什么

### 1. 播放源注册表（`js/00-bootstrap.js`）

```js
const MEDIA_PLAYBACK_SOURCES = [
  { id: 'cdn',    label: '对象存储',      build: asset => CDN_BASE + '/' + asset },   // 配置了才有
  { id: 'github', label: 'GitHub Release', build: asset => MEDIA_RELEASE_BASE + '/' + asset }
];
```

- 开启方式：`js/00-config.js` 里 `MEDIA_CDN_BASE: 'https://cdn.example.com/tcg/media'`；
- 只接受 **https 绝对地址**（`http:` 混合内容会被浏览器拦、相对路径无法确认域名），
  非法值被静默忽略并保持单源；
- **未配置时行为与 10.27.2 逐字节一致**（候选链退化为单元素数组），
  这意味着本版即使不发新配置也零风险。

### 2. 候选链回退（`js/06-media.js`）

源② 从"单串直链"改为候选链 `_playCandidateChain()`：

- 主源 onerror（或 8 秒停滞超时）→ 自动试备源 → 才继续原来的别名 / 飞书 / CDN 回退；
- 只有**成功那个源**的 URL 会写进落盘缓存（避免把坏源写进缓存，下次仍秒开失败）；
- 每次尝试都带会话守卫：用户关掉播放器后不再继续拉流。

### 3. 源健康记忆（`MEDIA_SOURCE_HEALTH`，30 分钟 TTL）

- 某源"整段失败"后 30 分钟内排到候选链末尾——否则每个用户每次播放都要先撞一遍坏源，
  等于把"回退 ≤2s"变成人人交的税；
- **成功一次立刻恢复主源优先**：故障恢复不需要等 TTL；
- 全部源都被标记坏过时仍然按顺序试一遍，而不是直接空态（宁可慢，不可不看）；
- 存储是 localStorage 单键几十字节，隐私模式/配额满时静默降级为"不记忆"。

## 测试

`tests/test_v10273_playback_sources.js`（**31 断言**），全部跑真实源码（`node:vm`）：

- **A** 未配置 CDN：单源、URL 与旧格式逐字符相同（向后兼容）；
- **B/C** 配置与非法配置：CDN 在前、尾部斜杠归一化、`http:`/相对路径/空白被拒绝；
- **D** 未映射文件名 → 空候选（宁可空态也不乱播）；
- **E** 健康记忆：坏源靠后不删除、写盘、成功即恢复、31 分钟前的记录视为已恢复；
- **F** 候选链**真回退**：用假播放器实跑——主源失败→试备源→只缓存成功源→全失败才回调；
- **G** 接线守卫：`_playReleaseOrCloud` 必须用候选链（改回单串会被 G2 抓住）。
