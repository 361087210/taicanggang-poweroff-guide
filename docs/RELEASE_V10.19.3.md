# V10.19.3 诊断加固版 — 发布说明

> 版本号：10.19.3 ｜ versionCode：101903
>
> ⚠️ **本版是 10.19.2 的超集**：它**包含 10.19.2 的全部修复**（网页端登录修复 + linkKey 惰性迁移）。**只需更新这一次，无需先装 10.19.2 再装本版。**

## 一句话
在 10.19.2 登录修复之上：**新增**「**先自检、再升级**」——**本设备能不能完成安全升级，一眼可见**，失败时明确区分两种原因、不再静默；并**修复未登录时的返回行为**——从注册页按返回，不再进入应用内页面。

## 本次新增

- **新增（诊断）「关于」页 →「运行环境自检」**：显示 **安全升级所需加密能力：可用 / 不可用**。
  - 采用**实证探测**（真跑一次 PBKDF2/`crypto.subtle` 通路），而不是只看能力对象是否存在——因为密码哈希在加密能力不可用时会**静默降级**，App 仍能登录，所以"能登录"**并不能**证明加密能力可用。

- **修复（诊断）安全升级失败不再静默**，明确区分两种原因并给不同指引：
  1. **本设备不支持所需加密能力** → 指引：**换用较新的手机，或联系组长**（**不**提供"重试"按钮——重试对此无效，给了反而让人反复按）。
  2. **已生成连接键，但回传云端失败** → 指引：**检查网络后重试**，并提供 **「重试上传」** 按钮。

- **修复**：反馈提交的「APP版本」字段不再恒为 `Vunknown`（此前从错误的对象读取版本变量，恒取不到值）。

- **修复：未登录导航守卫**（用户报告的"注册页按返回"问题）
  - **未登录**时从**注册页 / 忘记密码页**按返回（App 硬件返回键、网页浏览器返回均走同一处理），**不再进入应用内页面**，而是一律回到**登录页**；此前会落到「我的」页。
  - 「我的」页**未登录**时的身份卡由**硬编码的"组长"文字**改为「**未登录**」——此前那两个字是静态占位文本，容易被误读为"已登录组长账号"。
  - **纵深防御**：已登录状态下不再能进入注册页。
  - ⚠️ **性质说明（避免误解）**：这是**显示 / 导航层**缺陷 —— 未登录时 `isLeader()/canEdit()` 均为 `false`，**触达不到任何组长操作**，**不涉及权限泄漏、不是安全事故**。本次修复消除的是"观感像已登录"的误导。

## 升级指引（必读）

> **第 1 步先看自检，再决定是否继续** —— 这是本版的核心价值：避免对着"登不进"反复试（登录失败 5 次会锁 5 分钟，反复试只会更乱）。

1. **先自检**：打开 App →「我的 → 关于」→ 看「**运行环境自检**」：
   - ✅ **可用** → 继续第 2 步；
   - ❌ **不可用** → **停止**：本机无法完成安全升级，请**换用较新的手机**，或**联系组长**。
2. 确认 App 已是 **V10.19.3**。
3. 打开 App →「**退出登录**」→ 用**手机号 + 密码重新登录一次**。
   - ✅ **不会丢失本机数据**：退出登录只清除登录会话，**不会**删除本机账号表与车型数据。
4. 若提示「**回传云端失败**」：检查网络后点「**重试上传**」。
5. 约 15 分钟后（镜像定时同步）回到网页端，用同一手机号 + 密码登录即可成功。
   - 想更快：由组长在 GitHub 手动触发 `sync-web-data` 工作流可立即同步。

> 只有"真正重新输入手机号 + 密码登录"才会补算连接键；"仅自动恢复登录态"不会。

## 备注

- 本版新增的"自检 + 两因区分"用于**把不可诊断的失败变成可诊断的失败**：若某台设备自检显示"不可用"，请把该机型反馈给开发，用于决定后续是否需要更进一步的兼容方案。
- 网页端登录仍需**每个账号先在 App 完成一次真正的登录**（这是 10.19.2 起的既有要求，本版不变）。
