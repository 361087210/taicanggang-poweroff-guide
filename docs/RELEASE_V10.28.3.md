# V10.28.3 回滚能力版

> 一句话：把"能不能回滚到任意历史版本"从口头承诺变成可核对的清单 + 可执行的通道 ——
> 版本清单、网页一键回滚、App 历史版本入口、云端备份恢复，四件事补齐。

## 为什么做这一版

审计 95 个 `v*` tag 后发现：

| 问题 | 数量 | 具体 |
| --- | --- | --- |
| 有 tag 但完全没有 Release | 6 | `v10.27.10`、`v5.6`、`v5.4`、`v5.3.6`、`v10.27.3`、`v5.3.2` |
| Release 是空的 | 2 | `v10.27.3`、`v5.3.2` |
| 只有一半产物 | 24 | `v10.28.1`（仅 IPA）、`v10.9.2`（仅 APK）及一批 v5.x–v10.13 老版本 |
| 同一版本多个重复 Release | 4 | `v10.19.1`（3 份）、`v10.26.2`、`v10.15.5`、`v10.9.2` |

更关键的是**没有任何回滚通道**：Pages 只部署最新提交，`version.json` 只指向最新版，
App 内没有历史版本入口，Android 也不允许 versionCode 变小覆盖安装。

## 改了什么

### 1. 版本清单 `releases_index.json`（可核对）

- `scripts/gen_release_index.js` 从 GitHub Tags + Releases 生成清单，逐版本标注
  `complete`（APK+IPA+sha256 齐）/ `partial`（缺件）/ `missing`（空发布）/ `unreleased`（无产物）
- 清单随 Pages 与 App 包一起发布，`--check` 可在 CI 里做漂移校验
- `.github/workflows/sync-release-index.yml`：新 Release 发布后、每天、手动都会刷新，有变化才提交

### 2. 网页端一键回滚

`.github/workflows/rollback.yml`：输入目标 tag + 二次确认串 → 用该 tag 的站点内容重新部署 Pages。

- 工作流文件从默认分支取，**站点内容从目标 tag 取**（两次 checkout），避免"旧 tag 没有发布脚本"
- 发布文件清单抽到 `scripts/prepare_pages.sh` 作为单一真源，正常发布与回滚共用同一份清单，
  不会出现"回滚后的站点和当时线上不一致"
- 部署后的站点带 `_rollback_info.txt`（回滚时间/目标版本/触发人）

### 3. App 内历史版本

「我的 → 历史版本」列出清单里全部版本：状态徽标、发布日期、APK/IPA 直链按钮。

- 明确提示：**Android 降级安装需先卸载当前版本**；iOS 用旧版安装包
- 清单读取失败时明确提示，不静默留白

### 4. 数据回滚（云端备份恢复）

数据页新增「从云端备份恢复」：列出 `APP数据备份/备份文件/` 下的 `vehicle_backup_*.json`（按时间倒序），
选择后下载并**复用本地导入的同一套逻辑**（格式兼容 + 同 ID 覆盖 / 新 ID 追加 + 二次确认），
不会静默清空本地数据。

### 5. 清理脏数据

删除 5 个重复 Release（保留资产最全的一份）与 2 个空 Release，**所有 tag 保留不动**。

## 已知边界

- 历史缺口只标注、不重建：旧 tag 的构建链（Gradle / Cordova 版本）早已变动，重建产物与当年不等价
- WebView 内无法直接安装 APK，历史版本按钮走系统浏览器下载，安装仍需人工确认
- 数据回滚是**合并**语义，不是"整体替换到某个时间点"；如需彻底回退请先用备份核对

## 升级与兼容

- 无破坏性改动；`releases_index.json` 是新增文件，缺失时历史版本入口降级为"加载失败"提示
- 本地导入流程的行为与 V10.28.2 完全一致（只是支持传入已解析数据）

## 测试
