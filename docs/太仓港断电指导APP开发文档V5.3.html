一、版本定位: 全链路真机问题修复版

V5.3针对现场反馈的8项问题逐一做了根因级修复。核心结论: 此前多数"真机必现、浏览器正常"的问题,根源集中在四条链路上:

链路根因V5.3方案
网络层飞书API响应不带CORS头,WebView(https://localhost源)内fetch被浏览器策略静默拦截新增cordova-plugin-advanced-http原生HTTP插件,httpFetch()统一适配层: APP走原生网络栈,浏览器回退fetch
媒体层①旧数据格式photos:['images/…']与UI期望的photoPaths不匹配;②43个视频引用的文件从未随项目分发(本地/GitHub均无)①启动幂等迁移+死链清洗;②视频四源回退链+组长上传补源机制
导航层Android硬件返回键走Cordova默认history.back(),与自研navHistory导航栈脱节handleHardwareBack()六级统一路由
数据层用户数据(账号/审批/备份)与项目产物混存于同一飞书文件夹;审批结果不上传,组员端永远看不到双仓分离+审批全链路闭环

二、八项问题修复明细

修复问题1 · 照片视频无法正常查看播放

照片根因: 提取脚本生成的旧格式photos:['images/image1.jpeg'](字符串数组)与UI期望的photoPaths:['vehicle_images/…']不匹配;且旧引用目录名images/与实际打包目录vehicle_images/不一致;数据中还存在49条指向不存在文件的死链引用。

照片修复:

  • 数据层: vehicles_data.js死链引用一次性清洗(161→118条,全部可命中真实文件)
  • 运行层: migrateLegacyMedia()启动幂等迁移(旧数组→photoPaths,目录名修正,photos统一为数量语义)
  • 防御层: 列表缩略图与详情页<img onerror>兜底占位,不再出现破图图标

视频根因: 43辆车的videoPaths引用vehicle_videos/*.mp4,但这些视频文件从未存在于本地项目或GitHub仓库,旧版CDN回退链接必然404。

视频修复(四源回退链):

源① 本地APK内 vehicle_videos/          (随包分发,当前为空)
源② 飞书云端 APP数据备份/vehicle_videos/  (组长通过APP上传的真实视频)
源③ GitHub jsDelivr CDN                  (视频同步到仓库后自动可用)
源④ 诚实占位"教学视频待补充"               (绝不伪造AI视频误导现场作业)
        ↑ 组长在占位页可见"上传本车视频"按钮(≤20MB,飞书单文件上限)

修复问题2 · 数据无法以文档形式分享到其他软件

根因: V5.2分享走base64 DataURL,微信/QQ/钉钉部分版本只识别文本不识别DataURL附件,表现为"分享面板弹出但对方收不到文件"。

修复: 分享优先级链重构——

① writeBlobToCache() 写入APP缓存目录 → file://真实文件路径分享  (微信/QQ/钉钉稳定识别)
② 失败回退 base64 DataURL (修正MIME与扩展名严格对应)
③ 再降级 Web Share API Level 2
④ 兜底浏览器下载

修复问题3 · 返回上一步操作逻辑问题

根因: Android硬件返回键未注册处理器,Cordova默认行为history.back()与SPA自研导航栈navHistory脱节,真机按返回键行为不可预期。

修复: handleHardwareBack()六级统一路由(与页面返回按钮完全一致):

优先级当前状态行为
1照片全屏查看器打开关闭查看器
2视频播放器打开关闭播放器(停止播放释放资源)
3任一弹层打开关闭最上层弹层
4登录页双击退出保护(防误触)
5主Tab(车辆/数据/我的)提示"再按一次退出",2秒内再按才退出
6子页面(详情/编辑/同步等)goBack()弹出导航栈上一页

浏览器预览环境同步支持: popstate事件走同一路由,网页版与APP行为一致。

新增问题4 · 飞书数据备份/更新 + 产物与数据分仓

备份失败根因: 真机WebView内所有飞书请求被CORS策略静默拦截(浏览器预览正常,真机必现,无任何报错提示)。

修复: httpFetch()统一适配层,全部飞书API调用(上传/下载/列表/删除/建目录)收口至此:

APP环境: cordova.plugin.http 原生网络栈发送 → 天然绕过WebView CORS
浏览器:  回退标准fetch (保留网页预览能力)
POST体:  按类型自动切换 json/utf8 序列化器

分仓设计(项目产物与用户数据物理隔离):

区域位置内容写入方
产物区飞书项目根目录APK/开发文档/测试脚本/代码/版本文件开发侧(自动化同步)
数据区APP数据备份/子文件夹(自动创建,懒加载缓存token)账号数据approved_users.json、注册申请pending_reg_*.json、备份文件、组长上传的教学视频vehicle_videos/APP运行时(用户操作)

数据区token缓存在localStorage(tcg_data_folder),避免每次同步重复目录探测;产物区同步永不触碰用户数据,用户数据更新永不污染产物区(已有E2E断言验证)。

修复问题5 · 跨设备注册审批收不到

根因链(三处断点): ①组长登录时拉取一次申请,此后不再拉取→错过后续申请;②组长审批后结果只存本地,不上传飞书;③组员端无审批结果拉取逻辑。

修复(全链路闭环):

组员注册 → 上传 pending_reg_{手机号}.json 到数据区
                ↓
组长端: 登录拉取 + 每60秒静默轮询 → 发现新申请 Toast弹提醒
                ↓
组长审批 → pushApprovedUsersToFeishu() 上传 approved_users.json
                ↓
组员端登录/重试 → 拉取审批结果 → 通过即可登录(跨网络/跨设备)

两台手机不在同一网络下亦可闭环: 所有状态交换都经由飞书云端数据区,无任何局域网依赖。

优化问题6 · 编程规范落实

  • 零空catch块(自动化断言扫描),异常全部console.error+用户可见Toast+同步日志三通道反馈
  • V5.3新增的12个核心函数100%覆盖JSDoc,注释解释为什么这么写(如四源链为何不伪造视频、file://为何优于DataURL)
  • 防御性编程: 所有API响应非空判断、媒体加载onerror兜底、8秒源加载超时保护、飞书上传20MB预校验
  • Tailwind/SheetJS/jsPDF/AutoTable/html-docx五库全部本地化(vendor/),零外链CDN,离线UI与导出完整可用

一键构建(Linux/macOS)

# 环境要求: JDK17 + Android SDK(34) + Gradle 8.x + Cordova 13
cd 项目根目录
./build_apk_v53.sh          # 同步www → 添加平台插件 → 签名Release构建
# 产物: release/太仓港断电指导V5.3.apk (已签名)

手动构建(Windows, 与旧版.bat等价)

set JAVA_HOME=C:\jdk17  &  set ANDROID_HOME=C:\Android\Sdk
copy demo.html tcg_app\www\index.html  &  xcopy /E /I /Y vehicle_images tcg_app\www\vehicle_images
xcopy /E /I /Y vendor tcg_app\www\vendor          # V5.3新增: 本地化依赖库
cd tcg_app  &  cordova build android --release -- --packageType=apk ^
  --keystore=..\keystore\tcg_release.keystore --storePassword=*** --alias=tcg_release --password=***

注意: V5.3起必须同步vendor/目录到www,否则白屏;必须包含cordova-plugin-advanced-http插件(config.xml已声明,新增插件后需cordova prepare)。
