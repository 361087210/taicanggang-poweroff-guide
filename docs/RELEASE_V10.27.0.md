# V10.27.0 资源库分页 + 车型信息双向强关联

> 一句话总结：资源库改为 50 条/页分页（首屏 DOM 约 304 KB → 44 KB），并与车型信息双向联动 —— 任一方的增删都会立即反映到另一方，且同步维护路径、计数与照片板块/标签。

## 背景

v10.26.0 打通云端实测后，资源库同时展示台账 + 孤儿，当前索引 314 项。原实现虽然有一次 400 条的上限，但首屏会一次性 `innerHTML` 建出 300+ 行，中低端安卓机首屏与滚动都有明显压力。

同时，资源库与车型详情虽然共用 `vehicle_sync_data.json`，但两份视图此前并不真正联动：

- 台账是发版快照，车型侧改了图，资源库不会跟着变；
- 资源库上传/删除只改 `photoPaths`，`photos` 计数与 `photoSections/photoLabels` 不跟着改；
- 删除中间某张照片时，后续照片会整体前移，顶替上一张的板块与标签。

## 本次改动

1. **分页渲染**：每页 50 条，底部「上一页 / 第 x/y 页 / 下一页」，越界自动钳制到有效页。
2. **筛选/搜索联动**：切换筛选、输入关键字时自动回到第 1 页。
3. **搜索不再整页重建**：只重画「计数 + 列表 + 分页」区域，输入框不失焦。
4. 其余能力不变：云端✓/✗ 标记、孤儿、组长上传/删除、云端预览、缺失清单导出。

## 车型信息 ↔ 资源库强关联

1. **车型改了 → 资源库立即看到**：列表合并「索引快照 + 车型当前引用」，车型侧新增/换图以「新增」状态出现；车型侧删掉的图，索引行自动隐藏，不再出现幽灵行。
2. **资源库改了 → 车型信息跟着更新**：上传/删除同时维护：
   - `photoPaths` / `videoPaths`
   - `photos` / `videos` 计数（此前只改路径，导出会读到旧数量）
   - `photoSections` / `photoLabels`（与照片**按下标一一对应**；删除中间项时同步剔除，避免后续照片顶替上一张的板块/标签）
3. **回写飞书**：资源库增删后 3 秒防抖复用既有上传管线，组员端与 cron 索引不再停在旧状态。
4. **云端核对不误报**：已知集合改为「索引 + 实时引用」并集，车型侧刚上传、索引尚未重建的照片不会被标成「云端有·台账无引用」。

## 清晰度（照片 / 视频）

此前链路是「先压 1600px/q0.9 → 上云再归一 1280px/q0.85」，最终云端照片只有约 100 万像素，放大到车架号就发虚；内置旧图更只有 433px。

- 本地压缩：`1600px/q0.9 → 2400px/q0.92`
- 上云归一：`1280px/q0.85 → 2560px/q0.9`
- 查看器高清升级阈值：`700 → 1600`（433px / 1280px 的旧图都会尝试热替换为云端高清版；云端不更大时静默维持）
- 视频不做二次压缩，质量取决于源文件；Release 上极小的历史视频（数百 KB）本身分辨率就低，建议重新上传原片

## 媒体缺失不阻断业务

媒体是车型信息的**补充**，不是前置条件：

1. 照片/视频分离上传失败（目录不可用 / 权限 / 网络）不再让整次同步失败 —— 车型文字信息照常上云，日志明确提示「媒体待重试 N 项」。
2. 上云副本会自动剔除仍未上云的 base64 媒体，并同步裁剪 `photoSections/photoLabels`，保证云端副本的路径、计数、元数据严格对齐；**本地数据不做任何删改**，下一轮保存/上传继续重试。
3. 从飞书拉取时保留本机尚未上云的 base64 媒体，避免一次拉取把待传照片/视频吞掉。
4. 资源库预览兼容「车型实时新增」行；图片/视频文件缺失时显示明确占位，不抛错、不影响其他操作。
5. 车型新增、编辑、删除、导出均不依赖媒体文件是否存在。

## 车型增删改查细化

- **新增/编辑**：拦截同名显示名称。媒体目录名即 `display`，同名车型会共用目录导致串车与归属门禁失败。
- **删除**：提示改为真实语义 —— 只删除车型记录，独享媒体保留在云端成为孤儿（可在资源库「核对云端」中清理），避免误删原件；共享媒体仅解除本车引用。
- **查询/详情**：照片、视频、板块、标签缺失时降级显示，不阻断详情页与导出。

### 关于改名

「目录名即归属」是项目的既有约定（见 `docs/RELEASE_V10.25.0.md`）。**给已有照片/视频的车型改名**仍需要迁移媒体目录与引用：

```bash
node scripts/migrate_vehicle_rename.js --apply
node scripts/feishu_media_gc.js --apply
node scripts/gen_media_mapping.js && node scripts/gen_media_library.js
```

CI 的「媒体归属门禁」会在改名未迁移时直接变红，不会静默放过。

## 兼容性

- 索引格式 `media_library.json` 无变化（仍是 `schemaVersion: 1`）。
- 无新增依赖；`file://` / `app://` / https 三种加载路径不受影响。
- 导出库按需加载沿用 v10.26.1 的实现，本版未改动。

## 工程

- `js/13-media-library.js`：`PAGE_LIMIT(400)` 上限改为 `PAGE_SIZE(50)` 真分页，新增 `setPage()`。
- `js/13-media-library.js`：新增 `liveAssetsOf / mergeAssets / mediaPatchOf / unlinkPathOf` 四个纯函数，负责双向联动、计数重算与元数据同步剔除。
- 测试 `tests/test_v10257_media_library.js`：扩到 **86 断言**；新增 M10（分页）、M11（双向联动）、M12（计数 + 元数据对齐）、M13（删文件时板块/标签同步剔除）。
- CI 新增「资源库索引一致性」门禁：`npm run check:media-library`（共享引用校验沿用主线已有的 `fix_shared_refs --verify`）。
- 版本七源同步：`10.27.0 / 102700`，`CACHE_NAME=tcg-poweroff-v10.27.0`。

## 升级注意

- Android 需安装 `versionCode 102700` 的新包（覆盖安装即可，本地数据与飞书配置保留）。
- 网页端如仍显示旧界面，清一次 Service Worker 缓存（缓存名已升版，通常自动更新）。
