三、云端数据分仓架构 (V5.7核心设计)

用户要求「项目产物与操作端备份/同步数据分开保存」。V5.7 将飞书云文档根目录 WdXUfZPkClI1audQxIYc90XRnWc 重组为两大独立区：

飞书根目录/
├── 项目交付产物/            ← 项目产物区(GitHub Release镜像 + 文档)
│   ├── APK安装包/           ← 每版本签名APK
│   ├── 开发文档/            ← 开发文档/测试报告/迭代计划
│   └── 测试报告/
├── APP数据备份/             ← 用户操作数据区(APP自动读写)
│   ├── 同步数据/            ← vehicle_sync_data.json (车型双向同步)
│   ├── 注册申请/            ← pending_reg_{phone}.json (组员申请)
│   ├── 审批结果/            ← approved_users.json (组长审批)
│   └── 备份文件/            ← vehicle_backup_{date}.json (手动全量备份)
└── (历史遗留文件, 建议归档至 项目交付V4.0(规范整理)/)
  • 读取兼容：组长拉取注册申请时同时读取新子目录与旧数据区根(V5.3-V5.6旧版APP上传位置)，按文件名去重，新旧版本APP混用不丢申请。
  • 写入隔离：所有APP用户数据写入子目录；项目产物(安装包/文档)仅由交付流程写入产物区，互不污染。
  • 缓存自愈：子目录token缓存于localStorage，操作失败自动清缓存重试一次(换飞书应用/云端文件夹重建场景)。

四、签名与CI/CD体系

4.1 签名密钥(安全红线)

重要：旧keystore(v5.3签名)因密码遗失已不可用，且曾误入公开git历史(已失效)。V5.7启用全新RSA-2048 keystore(有效期25年)，仅存于 GitHub Secrets，任何仓库/代码/文档中不出现密钥文件。v5.3旧版用户升级需先卸载旧版(签名变更)。
Secret用途
KEYSTORE_BASE64keystore二进制Base64，CI解码后签名
KEYSTORE_PASSWORDkeystore存储密码(32位随机)
KEY_PASSWORD密钥密码(同存储密码)
KEY_ALIAStcg_release

keystore原件与密码已随交付物提供(密钥与密码.txt + tcg_release_v57.keystore)，请离线妥善保管——丢失将无法再对已发布应用进行覆盖升级。

4.2 CI流水线关键步骤

  1. 版本推导：从 config.xml 读取 version/versionCode，杜绝硬编码漂移
  2. 资产校验：校验5个vendor导出库+图片数量≥100，缺失即失败(问题①防回归)
  3. 签名：Base64解码 → zipalign → apksigner(v1+v2, 兼容Android 7-14) → verify
  4. 发布：tag触发 → GitHub Release 附APK → 回写 version.json 下载地址(与APK内versionCode严格一致，修复旧版误报更新)

六、升级指引

  1. 新装机：直接安装 GitHub Release 或飞书「项目交付产物/APK安装包」中的 tcg_poweroff_v5.7.x.apk
  2. v5.4-v5.6升级：直接覆盖安装(同新签名体系)
