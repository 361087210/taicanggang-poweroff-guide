## 本次解决的问题

### 1. 照片明明在，App 却报「缺失」（31 条）

**现象**：组长在飞书云盘或仓库里能看到照片，App 里却是「照片缺失」。

**根因**：V10.25.0 的迁移脚本把「被 2 个以上车型引用」的文件统一移进了 `vehicle_images/_共享/`，
但**没有回写引用**。数据里仍然写着 `vehicle_images/<车型>/image4.jpeg`，文件却在 `_共享/image4.jpeg`。
浏览器端对已成型的三段式路径原样放行，于是这 31 条永久 404。

**修复**：新增 `scripts/fix_shared_refs.js`（幂等，支持 `--dry-run` / `--verify`），
回写 `vehicles_data.js` 与 `web-data` 镜像中的引用。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 照片可命中 | 163 | **194** |
| 引用失配 | 31 | **0** |
| 真缺失（需补拍） | 72 | 72 |

### 2. 上传后「该传的没传」或「显示成别人的图」

**根因**：上传幂等用一个**扁平的文件名集合**跨所有车型目录判重。
A 车型目录里有 `image1.jpeg`，B 车型上传自己的 `image1.jpeg` 时会被判为「已上传」而跳过；
若解析时又按名字命中 A 的文件，就变成"张冠李戴"。

**修复**：幂等键改为 `车型目录/文件名`，并且作用域跟随**实际落盘目录**——
子目录创建失败降级到顶层时，作用域自动为空，避免用错键导致重复上传。

### 3. 上传失败时静默降级到顶层 → 云端散乱

`_ensureVehicleSubFolder` 原先在创建车型子目录失败时**静默返回顶层 token**，
照片全部堆在 `vehicle_images/` 根目录，只有一行 console 告警。
现改为：重试一次（含同名目录复列确认）→ 仍失败则抛错，外层记为 failed 并保留本地
base64 下轮重试。**宁可这次没传，也不要在云端留下无法归属的散文件。**

### 4. 客户端没有任何路径兜底

**修复**：新增 `mediaCandidateSrcs()`，加载失败时依次尝试：
`原路径 → _共享/同名 → 顶层/同名`，全失败才回退飞书云端，最后才显示「缺失」。
只试"同名不同目录"，绝不跨名猜测——断电教学照片看错车型是现场安全问题。
列表缩略图同步接入。

## 新增工具

### `scripts/transcode_videos.js` —— 视频批量转码

零成本视频方案（免费 CDN）的执行器：

```bash
node scripts/transcode_videos.js --check      # 检查 ffmpeg
node scripts/transcode_videos.js --dry-run    # 只列计划
node scripts/transcode_videos.js              # 转码 vehicle_videos/ → dist/videos-720p/
```

- 720p / 1080p 预设，CRF + maxrate 控码率
- **`+faststart`** 把 moov 前置 → 边下边播（这是"秒开"的物理前提）
- 输出按 `原名__内容SHA8.mp4` 命名：天然去重 + 可永久缓存
- 超过 20 MB 自动提示（jsDelivr 单文件上限），产出 `transcode-report.json`

实测：`18.5 MB → 1.4 MB`，输出校验 `ftyp → moov → free → mdat`，H.264 720p + AAC。

### `scripts/feishu_media_gc.js` —— 飞书云端对账整理

解决"云端散乱 + 只增不减"：

```bash
export FEISHU_APP_ID=cli_xxx FEISHU_APP_SECRET=xxx
node scripts/feishu_media_gc.js            # 预览（默认）
node scripts/feishu_media_gc.js --apply    # 执行移动/归档
node scripts/feishu_media_gc.js --apply --purge   # 连同回收站一起删（不可恢复）
```

以 `vehicles_data.js` 的引用为**唯一真源**，对云端做四类判定：

| 判定 | 动作 | 可恢复 |
|---|---|---|
| 位置归位 | 顶层/错目录的同名文件 → 移到 `车型目录/` | ✅ |
| 孤儿归档 | 清单无引用的文件 → `_回收站/<日期>/` | ✅ |
| 缺失报告 | 清单有、云端无 → 输出补传清单 | — |
| 歧义不猜 | 同名对应多个车型 → 只报告，不动手 | — |

**刻意不做推断式改名**：改名需要知道新名字（含内容哈希），云端无从推断。
规范命名由上传侧保证；存量旧名文件只要应用还在引用就"只挪位不改名"，
等应用切到新名字后，旧文件自然变成孤儿再归档。

### `scripts/fingerprint_videos.js` —— 视频内容指纹

`通用断电视频.mp4` 被 15 个车型共用，但此前没有 sha256，「是同一段视频」只是约定。
本脚本在持有本地视频的机器上生成 `docs/video_fingerprints.json`，
manifest 自动填入指纹，使"共用"变成**可验证事实**。
