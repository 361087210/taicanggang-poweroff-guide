3. 核心架构设计

3.1 网络层统一适配（httpFetch）

所有飞书 API 请求经 httpFetch() 统一出口：APP 环境走 cordova-plugin-advanced-http 原生网络栈（绕过 WebView CORS 限制），浏览器环境回退 fetch。这是 V5.3 修复真机所有飞书请求静默失败的关键层。

3.2 多源版本探测（fetchUpdateInfo）

更新检查并发探测 4 个源后取版本号最高的一条：jsDelivr CDN → GitHub raw → GitHub Contents API(base64解码) → 飞书 version.json。不做"首个成功即返回"——CDN 缓存滞后会误判"已是最新"。每个源 8 秒超时防弱网挂起。

3.3 同名多档确定性读取（V5.3.2）

飞书产物区存在历史分页缺陷遗留的同名多档，downloadJsonFromFolder() 用 reduce 取 modified_time 最新一份，消除列表顺序不确定性。

3.4 硬件返回键统一路由（V5.3）

Android 返回键按优先级路由：关全屏查看器 → 关视频播放器 → 关弹层 → 登录保护(不退出) → 主Tab双击退出 → 子页面返回上一步，与页面内返回按钮行为完全一致。

3.5 数据分仓

飞书云端两个物理隔离的文件夹：产物区(文档/APK/代码，应用只读+幂等替换)与「APP数据备份」(账号/审批/备份，应用读写)。用户数据永不污染项目产物。

4. V5.3.3 安装包直链下载机制

4.1 需求与方案

此前更新分发依赖"飞书云盘人工翻找"或标注"需仓库权限"的 GitHub 页面跳转，且 version.json 的 apkUrl 指向不存在的大写 V5.3 标签资产（404 断链）。V5.3.3 改为 Release 资产直链一键下载：公开仓库的 Release 下载 URL 无需任何鉴权，系统浏览器打开即触发 Android 原生下载管理器。

4.2 直链解析三级回退（resolveApkUrl）

function resolveApkUrl(info){
  // L1: CI按实际Release资产回写的downloadUrl(新标准字段)
  if(info.downloadUrl && /^https:\/\//.test(info.downloadUrl)) return info.downloadUrl;
  // L2: 兼容旧字段apkUrl, 过滤已知V5.3大写tag断链
  if(info.apkUrl && /^https:\/\//.test(info.apkUrl) && !info.apkUrl.includes('/download/V5.3/')) return info.apkUrl;
  // L3: 按CI产物命名规则推导兜底: v{version}/taicanggang-V{version}-b{build}.apk
  return `https://github.com/${GITHUB_REPO}/releases/download/v${info.version}/taicanggang-V${info.version}${info.buildNumber?('-b'+info.buildNumber):''}.apk`;
}

三级回退保证任何历史版本的 version.json 都能解出可用直链——包括尚未升级到 V5.3.3 的存量设备。

4.3 更新弹窗交互

发现新版本弹窗 → 主按钮「直接下载安装包(推荐)」(绿) → downloadApkDirect() → openExternal(直链) → 系统浏览器 → Android下载管理器 → 通知栏点击安装
        └ 备用按钮「飞书云盘下载」(蓝) → 打开产物区文件夹人工下载

选择系统浏览器而非应用内 cordova-plugin-file 下载的原因：应用内下载需申请存储权限，且部分国产 ROM 分区存储策略下失败率高；系统通道零权限、断点续传、通知栏进度条均为原生体验。旧入口 downloadUpdate() 保留并入直链通道，向后兼容。

4.4 CI 自动回写直链

android-release.yml 在构建产物重命名后回写 version.json：直链 URL 按规则预计算（releases/download/{tag}/{apk_name}），与 softprops/action-gh-release 实际上传的资产名严格一致；同时回写真实 apkSize。仅 tag 触发且非 dry-run 时写入，防止测试构建产生断链。

实测验证：v5.3.2 已发布资产直链 HEAD 探测返回 200；v5.3.3 直链在 CI 发布后由专项测试 test_v533_direct_download.js D5 节复验可达性。

5. 数据体系与飞书集成

5.1 车型数据

vehicles_data.js 导出 VEHICLES_DATA 数组：49 个车型，每条含品牌/车系/配置/断电位置/分步步骤(steps)/关键帧(keyFrame)/备注/照片引用(photoPaths)/视频引用(videoPaths)。照片资产随 APK 分发(vehicle_images/)，视频走四源回退链。

5.2 媒体回退链

类型回退顺序
视频本地APK资产 → 飞书云端(APP数据备份/vehicle_videos) → GitHub CDN → 诚实提示"待补充"
照片本地缩略图/详情图/全屏 → 飞书云端(APP数据备份/vehicle_images) → 加载失败占位兜底

5.3 协同与审批

组员数据上传 vehicle_sync_data.json 至数据区；注册审批跨设备闭环：组员申请 → 组长60秒轮询+Toast提醒 → 审批结果上传云端 → 组员端拉取状态。登录鉴权与角色(组长/组员)本地管理，敏感操作双人确认。

5.4 飞书 API 要点

  • 认证：tenant_access_token(internal app)，App Secret 由用户在设置页手动填写，零硬编码
  • 列目录：drive/v1/files?folder_token= 翻页字段为 next_page_token(非page_token)，超200项必须翻页
  • 上传：≤20MB 走 upload_all multipart 直传
  • 下载：drive/v1/files/{token}/download，原生HTTP通道需处理UTF-8 BOM与ArrayBuffer解码
  • 删除：应用身份仅能删除应用自己上传的文件(错误1062501=人为所有档无权)，故同步策略为"删自己旧档→传新档"幂等替换

6. CI/CD 构建发布体系

Android Release Buildpush tag v*签名构建APK → 回写version.json(buildNumber/downloadUrl/apkSize) → 提交main → 发布GitHub Release

6.1 构建号体系（独立递增）

android-versionCode = BASE_VERSION_CODE + run_number，V5.3.3 起 BASE=50303。同名版本重发不冲突，CI 产物 versionCode 恒高于手机构建，安装升级永不被拒。产物命名 taicanggang-V{版本}-b{run_number}.apk。

6.2 APK 产出三重保险（V5.3.2 修复）

cordova-android@13 默认执行 bundleRelease 产出 AAB 而非 APK：① build.json 显式 packageType=apk；② 命令行 --packageType=apk；③ 未检出 APK 时 Gradle assembleRelease 兜底。产物路径多级回退探测。

6.3 签名安全（V5.3.3-b5 重大修复）

keystore 与密码全部走 GitHub Secrets（KEYSTORE_BASE64/KEYSTORE_PASSWORD/KEY_ALIAS），Runner 上解码注入，仓库与日志零明文。

签名注入修复（本次发布核心修复）：cordova-android@13 在 --buildConfig=build.json 模式下只认 build.json 内的 android.release 签名字段，workflow 此前仅写 release-signing.properties 被静默忽略，构建日志告警 'keystore' and 'alias' need to be specified，导致 V5.3.2-b3 / V5.3.3-b4 两个 Release 产物实际未签名（下载后安装报"应用未安装"）。修复：① 签名四要素（keystore/storePassword/alias/password/keystoreType）经环境变量写入 build.json，不落仓库；② 新增「校验APK签名」发布关卡——检测 APK Signing Block v2/v3 魔数必须紧邻 Central Directory，未签名直接构建失败，从结构上杜绝坏包发布。

6.4 发布流程

git tag v5.3.3 && git push origin v5.3.3
# → Android Release Build 自动: 构建→签名→回写直链→Release发布
# → APP端: 检查更新 → 多源探测到5.3.3 → 弹窗「直接下载安装包」→ 一键升级

7. 安全体系

  • 凭证零硬编码：App Secret 设置页手动填写(V5.3.1加固)；测试脚本环境变量读取；CI 密钥走 Secrets

  • CodeQL 每次推送自动扫描
  • 权限模型：组员只读，上传/审批/数据管理限组长；敏感操作确认弹窗

10. 二次开发指引

10.1 日常迭代

  1. 改 demo.html(唯一源码真身) + version.json(版本/changelog) + config.xml(versionCode)
  2. 同步升 CI 工作流 APP_VERSION 与 BASE_VERSION_CODE(=主版本号×10000+次×100+修订)
  3. 跑 python3 tests/test_v53_fixes.py 与专项测试全绿
  4. commit → push main(CI/CodeQL验证) → 打 tag v{版本} 触发 Release 构建
  5. 运行 scripts/sync_feishu_v53.py 同步产物到飞书(或交付会话内一键同步)

10.2 新增车型

在 vehicles_data.js 追加条目；照片放 vehicle_images/(引用相对路径)；教学视频上传飞书数据区 vehicle_videos/(按文件名回退匹配)。

10.3 更新分发约定（必须遵守）

  • Release tag 一律小写 v 前缀(v5.3.3)，资产名含构建号
  • version.json 的 downloadUrl 由 CI 回写，手工发布时必须与资产名逐字符一致
  • 飞书产物区同名文件遵循"保留 modified_time 最新"约定，旧档删除见清理清单
