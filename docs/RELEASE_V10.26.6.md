# V10.26.6 发布说明（清晰度与韧性版）

- **发布日期**：2026-11-23
- **版本号**：10.26.6（versionCode 102606）
- **一句话总结**：照片画质退回无损、并把「太模糊」的真因量化出来（**170 项素材源分辨率不足**）；同时补齐「媒体缺失不崩」「改名自愈」「增删改查守卫」。

## 一、照片/视频「太模糊」——先说结论

| 结论 | 证据 |
|---|---|
| **主因是源图分辨率低**，不是编码问题 | 实测 186 张可测照片中 **170 张宽 < 900px**，最常见 `433×606`；手机屏 2x/3x DPR 下会被放大显示 |
| 上一版我的"调色板压缩"雪上加霜 | 12 张 PNG 从 4.96MB 压到 1.89MB，照片类图量化到 256 色会有色带 |
| 视频也一样 | Release 里的视频最高 **1280×720**，个别仅 **406×720**（竖屏裁切后） |

### 这一版做了什么

1. **撤回调色板压缩**：12 张 PNG 恢复无损（1.89MB → 4.96MB）。宁可多 3MB（懒加载 + 缓存兜底），不牺牲画质。
2. **把"低清"变成可见问题**：资源库索引新增每张照片的宽/高，**宽 < 900px 标「低清」并显示尺寸**；顶部提示「低清 N 项」；新增「低清」筛选（当前 **170 项**）。
3. **给出明确补拍标准**（建议写进现场规范）：
   - **照片**：短边 ≥ 900px，推荐 **1200–1600px**（手机拍原图直传，别用微信"压缩后发送"）
   - **视频**：≥ **1080p**；现有 720p 无法通过转码变清晰，只能重拍/重传

> 注：视频转码脚本 `transcode_videos.js` / `publish_media_release.js` 目前按 720p 瘦身；若现场能提供 1080p 源片，可把目标码率与分辨率上调（流量会涨约 2–2.5 倍），需要你确认。

## 二、媒体只是「补充」——缺了也必须能正常工作

| 场景 | 行为（已由测试钉住） |
|---|---|
| 照片 404 / 视频丢失 | 候选路径回退（原路径 → `_共享` → 顶层）→ 全失败显示占位，**不抛异常** |
| 删除车型 | 只删车型信息（`splice` + 持久化 + 审计），**不删任何文件**；确认文案已从"将同时删除云端照片/视频"改为**"仅删除车型信息，照片/视频文件会保留（可在资源库清理）"** |
| 资源库索引缺失/损坏 | 本地 fetch → XHR → 线上 Pages 三级兜底；全失败显示错误 + 重试按钮，**不白屏** |
| 导出（Word/PDF/Excel） | `preparePhotoMapSafe` 逐张容错，缺图跳过；导出主体不受影响 |

## 三、车型 ↔ 资源库 强关联：从"能看出"到"自愈"

1. **改名自愈**：同步流水线新增 `migrate_vehicle_rename.js --apply`（幂等；冲突只报告不动手），随后校验 **"无待迁移项"**，否则流水线红。改名后媒体目录与引用自动跟随，不再停留在"改名失配"。
2. **断链可见**（v10.26.5 已有）：无主目录 / 改名失配 / 无素材三类都在资源库「断链」筛选里。
3. **重名守卫**（本版新增）：新增/改名时**显示名唯一**校验 —— 同名会让两台车落到同一个媒体目录（串档），事后极难拆；编辑时排除自身避免误拦。

## 四、车型增删改查细化

| 操作 | 校验/行为 |
|---|---|
| 新增 | 显示名/断电位置必填；尺寸须 `数字*数字*数字`；**显示名不得重复**；品牌/车系/配置走选择器（避免错别字分裂） |
| 编辑 | 同新增；**重名校验排除自己**；修改显示名会触发下次同步的自动迁移 |
| 删除 | 二次确认；按 manifest 区分"共享媒体（仅解除本车引用）"与"独享媒体（文件保留）"；写审计 `vehicle.delete` |
| 查询 | 品牌/系列/配置三级筛选 + 搜索；最近查看持久化；`pinyin` 随显示名更新 |
