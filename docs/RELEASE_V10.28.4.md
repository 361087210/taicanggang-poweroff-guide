## 改了什么

### 1. 同名备份无法区分（数据回滚)

`APP数据备份/备份文件/` 里有 `vehicle_backup_2026-10-03.json` 两份、`2026-09-06` 与 `2026-09-06(1)` 各一份。
原来的恢复按**文件名**找 `modified_time` 最新的一份，所以点列表里任何一条都只能拿到最新那份。

- 新增 `downloadJsonByFileToken(token, fileToken)`，`downloadJsonFromFolder` 复用它（行为不变）
- 云端备份恢复改为**按 file token 下载**，列表按钮直接带 token
- 列表时间精确到秒，同名文件一眼可分

### 2. 入口与「关于 → 版本历史」重名

「关于」页本来就有静态的「版本历史」（更新日志）。我加的入口也叫「历史版本」，实测时连我自己都点错了。

- 入口改名 **安装包回滚**，副标题「历史版本 · 可回滚到任意已发布版本」
- 弹层标题 **安装包回滚（历史版本）**

### 3. 备份大小显示为空

飞书列表对这批备份返回 `size: null`，此前会渲染成「时间 · 」。改为无大小时只显示时间。

## 随本版一并修复的工作流缺陷

这两个是回滚实测时撞出来的，已单独合并但由本版一起计账：

1. `rollback.yml` 产物校验步骤的 heredoc 打断了 YAML 块标量 → 改为 `jq` 解析
2. `prepare_pages.sh` 先 `cd "$SRC"` 再用相对路径输出，回滚时把 `_publish` 建到了 `site/` 里 → 输出目录改为按调用者目录转绝对路径

新增两条守卫：所有工作流必须能被 YAML 解析；`prepare_pages.sh` 源/输出分离时产物必须落在调用者位置（真跑脚本，不做文本匹配）。

## 升级与兼容

- 备份恢复仍是**合并**语义（同 ID 覆盖 / 新 ID 追加），恢复前二次确认
