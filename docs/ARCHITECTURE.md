## 二、数据流设计

### 2.1 车型数据双向同步

```
本地 VEHICLES 数组
      │
      ▼
┌─────────────┐     增量对比(id+timestamp)     ┌─────────────┐
│  上传 Push   │ ──────────────────────────────▶ │ 飞书 Bitable │
│ syncVehicles │                                │ 多维表格     │
│   ToBitable  │ ◀────────────────────────────── │             │
└─────────────┘     智能合并(新增/更新/跳过)      └─────────────┘
      │
      ▼
本地 IndexedDB (持久化)
```

### 2.2 审批流

```
新用户注册
    │
    ▼
创建审批实例 ──▶ 飞书审批中心
    │                │
    │                ▼
    │           组长审批操作
    │                │
    ▼                ▼
  轮询查询 ◀──── 审批状态变更
    │
    ▼
更新本地用户状态 (pending → active)
```

### 2.3 全量备份

```
本地数据(车型+用户+日志)
    │
    ▼
JSON 序列化
    │
    ▼
压缩 Blob ──▶ 飞书云文档 / APP数据备份 /
              full_backup_YYYYMMDD_HHMMSS.json
              (保留最近 10 个快照)
```

## 三、冲突解决策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 云端新增本地无 | 直接添加 | 拉取时追加到数组 |
| 云端本地都有 | 按时间戳 | `onConflict: 'newer'` 默认 |
| 本地修改未上传 | 上传覆盖 | 组长权限可强制上传 |
| 审批状态不一致 | 以飞书为准 | 轮询时同步 |

## 四、错误处理与重试

```
API 请求
   │
   ├─ 成功 ──▶ 返回数据
   │
   └─ 失败 ──▶ 重试(最多3次, 指数退避)
          │
          ├─ 成功 ──▶ 返回数据
          │
          └─ 失败 ──▶ 记录日志 + Toast 提示用户
                     + 降级到本地缓存数据
```

## 五、安全设计

1. **Token 管理**: 自动缓存 2 小时，提前 5 分钟刷新
2. **权限最小化**: 仅申请必要的 Android 权限
3. **数据隔离**: 车型数据与用户数据分离存储
4. **备份加密**: 未来可扩展为上传前 AES 加密
