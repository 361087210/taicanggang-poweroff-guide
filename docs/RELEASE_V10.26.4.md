# V10.26.4 发布说明（视频指纹版）

- **发布日期**：2026-11-23
- **版本号**：10.26.4（versionCode 102604）
- **一句话总结**：62 条视频引用里 **59 条已有 sha256**（此前 0 条），两个共享视频 **100% 覆盖**——同名换片从此可被发现。

## 为什么

视频不入仓库（存 GitHub Release / 飞书），manifest 里的 `sha256` 长期为空。于是「`通用断电视频.mp4` 被 13 个车型共用」只是**约定**，不是可验证事实：一旦有人用同名文件替换，13 个车型会**静默**变成错片，审计也发现不了——而这类内容错误在断电指导场景里是现场安全问题。

## 做了什么

### 🟢 指纹入库（92 条）

`docs/video_fingerprints.json`：

- **46 个原始文件名**（如 `通用断电视频.mp4`）——数据/manifest 里引用的名字
- **46 个资产名**（`tcgv_<hash>.mp4`）——Release 里的实际文件，便于反查
- manifest 覆盖率 **46/49 = 94%**；`audit:media` → **视频指纹 59/62 已有 sha256**（此前 0/62）
- **共享视频 100% 覆盖**：`通用断电视频.mp4`（13 台）、`长安UNI__UNI_T.mp4`（2 台）→ C8「共享视频无内容指纹」告警**消失**

### 🛠 为什么在 CI 生成，而不是本地

本地实测下载 Release 资产只有 ~50KB/s（449MB 要几个小时）；GitHub Runner 拉自家 Release 是内网速度，**2 分钟**跑完。

新增工作流 **`Fingerprint Videos`**：

```
下载映射表点名的资产 → fingerprint_videos --release-map → 重建 manifest/索引 → 有变化才提交
```

- `--release-map` 是本次补的关键能力：Release 里叫 `tcgv_xxx.mp4`，数据里叫「通用断电视频.mp4」，不映射就永远填不上 manifest
- **每周一 03:00 UTC 自动复查**：任何人替换了同名视频，下一次 diff 里立刻可见（连带 size 变化）

### 🔧 脚本增强

- `fingerprint_videos.js --release-map <path>`：资产名 → 原始名反向映射，一个资产回填到它对应的所有原始名
- `--check`：会明确提示「本地目录缺少这些已入库指纹的视频」，不再误报为指纹变化

## 验证

- 新增 `tests/test_v10264_video_fingerprints.js`（**20 断言**）：指纹形态（64 位 hex、size>0）、映射生效（原始名+资产名都在）、manifest 覆盖 ≥90%、**共享视频 100%**、C8 告警消失、工作流接线、`--release-map` 实现
- `audit:media` 输出：`视频指纹: 59/62 已有 sha256`，且**不再有 C8 告警**
