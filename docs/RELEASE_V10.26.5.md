# V10.26.5 发布说明（车型 ↔ 资源库 强关联版）

- **发布日期**：2026-11-23
- **版本号**：10.26.5（versionCode 102605）
- **一句话总结**：任意一方变更后，另一方都能**看出对不上**——删车留下的无主目录、改名后指向旧目录的引用、新增但还没有素材的车型（此前资源库里根本看不到这台车）。

## 检查结论（改之前）

逐条核对「车型信息 ↔ 媒体资源」的联动，发现 4 处是**静默**的：

| 变更 | 改之前的表现 | 结果 |
|---|---|---|
| 车型**改名** | 引用仍写旧目录 → 资源库只显示"缺失"，看不出是改名 | ❌ 静默 |
| 车型**删除** | 旧照片目录留在磁盘上 → 既不在"孤儿"列表（只扫 `_未归类/`），也不在任何统计里 | ❌ 隐形 |
| 车型**新增**（无素材） | `assets` 只从"声明过的照片/视频"生成 → 这台车在资源库里**一条都不出现** | ❌ 看不见 |
| App 内索引**过期** | 索引是打包快照；线上索引兜底被 CSP 挡住（`connect-src` 没有 github.io） | ❌ 被拦 |

（`sync → gen_vehicles_data → gen_media_mapping → gen_media_library` 这条主链路本身是统一的，`migrate_vehicle_rename.js` 也能修仓库侧改名——缺的是**发现与呈现**。）

## 这一版补的

### 1. 索引里加三组数据（`media_library.json`）

```jsonc
"vehicles": [ { "id":1, "display":"比亚迪海豚DOLPHIN(低配)", "folder":"…",
                "photos":3, "videos":1, "missing":0, "noMedia":false } ],   // 含 0 素材车型
"unownedFolders": [ { "folder":"旧车型名", "files":4 } ],                    // 有文件、无车型引用
"renamedRefs":   [ { "id":7, "display":"新名字", "fileName":"a.jpeg",
                     "declared":"vehicle_images/老名字/a.jpeg",
                     "foundAt":"vehicle_images/新名字/a.jpeg" } ]             // 改名失配
```

`stats` 同步增加 `vehiclesWithoutMedia / unownedFolders / renamedRefs`。

### 2. 资源库界面能看见

- 顶部提示条：**⚑ 车型与资源有 4 处对不上：4 台无素材 · 0 个无主目录 · 0 条改名失配**（可点）
- 新增「断链」筛选：三类各带专属标签（无主目录 / 改名失配 / 无素材）
- 改名失配行直接写「车型 → 文件在「新目录」」，不用再去翻日志

当前数据：100 台车型、**4 台无素材**（比亚迪秦/宋PRO/汉/驱逐舰05）、0 个无主目录、0 条改名失配。

### 3. 改名检测抽成纯函数并加反例

`detectRenamedRefs()`：只在**别的车型目录**里找到同名文件才算改名失配；命中 `_共享/` 或 `_未归类/` 时**不算**（那两种有各自的状态），避免误报。

### 4. App 内可取最新索引

`connect-src` 放行 `https://361087210.github.io`，本地索引缺失/过期时模块会回落到线上索引（加载顺序：本地 fetch → XHR → 线上）。

## 现在的一致性矩阵

| 变更发生在 | 另一方怎么同步 |
|---|---|
| 车型改名 | 仓库侧：`migrate_vehicle_rename.js` 搬目录+回写路径；未搬时 → 资源库「改名失配」显式标出 |
| 车型删除 | 资源库「无主目录」列出（带文件数） |
| 车型新增（无素材） | 资源库「无素材」列出 + 顶部提示 |
| 上传/删除照片视频 | 同步 → 重建 manifest/索引（15 分钟 cron + 可手动「刷新」拉到线上最新） |
| 云端数据变更 | `sync_web_data` → `gen_vehicles_data` → `gen_media_mapping` → `gen_media_library` 全链重算 |

## 仍建议后续处理

1. **改名自动迁移**：目前改名后要么人工跑 `migrate_vehicle_rename.js`，要么长期停在「改名失配」；可考虑在同步流水线里对失配引用做"存在性优先"自动回写（与 v10.26.3 的 `_共享` 回写同一套思路）
2. **删除车型时清理媒体**：现在只会变「无主目录」，是否自动归档到 `_未归类/` 需业务确认（涉及删数据）
